# @wolfsblvt/icons 0.3.0

Bluesky joins the curated brand catalogue. Works-authored surfaces can now show a Bluesky link from the shared package, next to GitHub and Discord, instead of copying the mark locally.

## Highlights

- **`bluesky`** resolves through `getBrand("bluesky")` and `<BrandIcon name="bluesky" />`. It is the current Simple Icons mark, monochrome only, referenced from the `@iconify-json/simple-icons` dependency exactly like `github` and `discord`; no third-party bytes are vendored.
- Its source revision, licence (CC0-1.0 for the icon data), trademark note and brand-guideline link are recorded in [`src/metadata/brands/bluesky.json`](https://github.com/Wolfsblvt/wolfsblvt-icons/blob/v0.3.0/src/metadata/brands/bluesky.json), and the [third-party notices](https://github.com/Wolfsblvt/wolfsblvt-icons/blob/v0.3.0/third-party-notices.md) name it. The Bluesky name and logo remain Bluesky Social PBC's; showing them implies no affiliation.

```astro
---
import { BrandIcon } from "@wolfsblvt/icons/astro";
---

<BrandIcon name="bluesky" />
```

## Upgrade

```bash
npm install @wolfsblvt/icons@0.3.0
```

No existing name changed meaning or geometry. `0.3.0` also carries everything from `0.2.0`, including the Wolfsblvt Works glyphs `wolfsblvt/works` and `wolfsblvt/signpost`.

## Proof and current limits

The release source passed the repository verification suite, including a real Astro consumer build and a clean consumer that installs the packed tarball before building through its public exports. It is published from GitHub Actions through npm Trusted Publishing and carries npm provenance.

`0.3.0` is still an early package release, not a stability promise.
