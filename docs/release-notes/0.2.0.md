# @wolfsblvt/icons 0.2.0

The Wolfsblvt Works umbrella identity arrives in the package. `wolfsblvt/works` and `wolfsblvt/signpost` are now available product glyphs, so the Works website and any Works-authored surface can take them from the shared catalogue instead of keeping a local copy.

## Highlights

- **`wolfsblvt/works`** is the compact Works mark for footer, social, provider and project-picker slots where the formal `WOLFSBLVT / WORKS` lockup does not fit: the mark's two open corners and its offset dot on the 24 grid. It was reserved as `planned` in 0.1.0 and now resolves.
- **`wolfsblvt/signpost`** is the pencil-sketched three-board signpost from the Works website's personal navigation. It is Works wayfinding, not a replacement for `lucide:signpost` in ordinary directional UI.
- The [Wolfsblvt Works family map](https://github.com/Wolfsblvt/wolfsblvt-icons/blob/v0.2.0/docs/product-families/wolfsblvt.md) records the meaning, source and usage rules, with a 16 to 32 px light and dark contact sheet.

```astro
---
import { ProductIcon } from "@wolfsblvt/icons/astro";
---

<ProductIcon name="wolfsblvt/signpost" />
```

## Upgrade

```bash
npm install @wolfsblvt/icons@0.2.0
```

No existing name changed meaning or geometry. Code that expected `resolveProductIcon("wolfsblvt/works")` to throw because the glyph was planned now receives the glyph.

## Proof and current limits

The release source passed the repository verification suite, including a real Astro consumer build and a clean consumer that installs the packed tarball before building through its public exports. This is the first release published from GitHub Actions through npm Trusted Publishing, so it carries npm provenance.

`0.2.0` is still an early package release, not a stability promise.
