# @wolfsblvt/icons 0.1.0

One curated icon language is now available as an installable package for Wolfsblvt Works products. `@wolfsblvt/icons` lets Node and Astro developers use stable UI meanings, selected brand marks, and Works-authored product glyphs without a runtime icon CDN or a copy-pasted SVG collection.

## Highlights

- Use a framework-neutral typed catalogue for semantic UI aliases, direct Lucide glyphs, curated brands, and namespaced product icons.
- Add the Astro adapter through `@wolfsblvt/icons/astro`, including `UiIcon`, `BrandIcon`, and `ProductIcon`.
- Keep runtime assets local: the package and consumer build emit inline SVG instead of requesting icon geometry from an external CDN.
- Inspect the source and provenance behind each route. Lucide supplies ordinary UI language, Simple Icons supplies admitted brands, and Works-authored glyphs carry their own metadata and visual standard.

## Install

```bash
npm install @wolfsblvt/icons astro astro-icon @iconify-json/lucide @iconify-json/simple-icons
```

The Iconify collection packages remain direct consumer dependencies so `astro-icon` resolution does not rely on incidental dependency hoisting. See the [Astro quick start](https://github.com/Wolfsblvt/wolfsblvt-icons#astro-quick-start) for the supported configuration.

## Proof and current limits

The release source passed the repository verification suite, including a real Astro consumer build and a clean consumer that installs the packed tarball before building through its public exports. Those checks prove the package and build boundary; they do not claim a hosted service or a future glyph family.

`0.1.0` is an early package release. The accepted `diffdevil/*` family is available; the compact `wolfsblvt/works` glyph remains planned until its own owner-selected visual contribution. Brand marks retain their owners' trademark and guideline terms, recorded in the package metadata and [third-party notices](https://github.com/Wolfsblvt/wolfsblvt-icons/blob/v0.1.0/third-party-notices.md).
